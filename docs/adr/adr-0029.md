## 背景

### 1. 前一份方案存在一个无法回避的漏洞

`docs/spec/archive/v1-zero-boundary-spec.md`（v1）提出删除 Cloudflare Container、
改用 Worker 原生采集以把成本降到零。但该方案自己在 §6 R1 记录了一个致命问题：

> "你连 10ms 能不能跑完都不知道，就在谈删容器。"

**单点探针是一张照片，不是一台仪器。** 它只能回答"某次调用是否够快"，无法回答"长期运行是否等价"。

### 2. 对照组的仪器其实早已建成，且已损坏 45 天

侦察确认：隔离的 preview 轨道（独立 Worker `news-sentry-api-preview`、独立 D1 `ns-db-preview`、
独立 R2、前端 API 绑定泄漏断言、精确 40-hex SHA 生产门禁、写入 canary、连续性账本）**已在仓库中建成**。
系统甚至在 `frontend/cloudflare/workers/api/health.ts:43-45` 写明了 `containerRequiredForEnvironment(env) { return env !== "preview"; }`。

但该仪器自 `04818fe`（2026-08-05）起不可用：KV 绑定复用了 D1 的占位 UUID，
使 `wrangler.toml` 中 `00000000-0000-4000-8000-000000000000` 出现 **3 次**，
而 `tools/cloudflare_preview_guard.py:88-92` 要求**恰好 1 次** → 任何 push 到 `preview` 都 exit 2。
覆盖该守卫的测试使用 `tmp_path` 合成 TOML，因此 CI 从未发现。

**结论：`建成了` 与 `可用` 之间，差的不是代码，是一次真实执行。**

### 3. 产品方向从未被裁决，且内部矛盾

2026-09-19 产品对齐问卷的结果存在四处硬矛盾：要收钱却判定没有护城河；
第一用户是机构却选择单人自用；要卖机构却要砍掉机构唯一入口；定位为"事实池展示面"却选择新闻列表首屏。

---

## 决策

### D1｜采用双轨对照，而不是单点探针

建立两条并行轨道：**对照组**（`main` / 生产 / Python Container 栈）与
**实验组**（`preview` / 新栈 / 无 Container）。所有"新方案更好"的断言必须在实验组产生，
并用两组同时观测的数据判定。

提升的唯一依据是**支配判定**（详见工程层 SPEC §3.4）：
六项指标无短板 + 至少三项严格优 + 连续 ≥28 个健康 6 小时槽位 + 对照组零损失，
且**同时满足绝对地板**（不依赖对照组，因为对照组自身 ok 率仅 74.10%）。

### D2｜产品基准方向（六条裁决）

| # | 裁决 | 要点 |
|---|------|------|
| P1 | 生意 vs 作品 | 过渡态：作品先行。**触发条件**：第一个真实用户连续使用 30 天 → 启动商业评估 |
| P2 | 第一个用户 | **个人专业用户**（记者/研究员），不是机构。机构延后 12 个月 |
| P3 | 管理后台 | 收敛为**审核 + 导出**两件事；运维/配置/用户管理回归 CLI。多用户 bug 冻结不修 |
| P4 | 公开站首页 | **canonical 对比视图**（一条事件 × 多国信源 × 溯源链）；完整 feed 降为次级 tab |
| P5 | 六个缺口 | 只修 **B(质量) → E(信任) → C(闭环)** 链条；A(覆盖) 只做核心层；D(分发)/F(成本) 冻结 |
| P6 | 语言方向 | **单向**：中文读者读外媒。英文/多语页面保留为 SEO 壳，不建反向翻译产品 |

护城河裁决：只建**信任壁垒**（归并质量 + 溯源可验证 + 校准门禁）。
时间壁垒（源矩阵）、成本壁垒、网络效应均不视为可依赖的护城河。

### D3｜技术栈与删除顺序

线上目标形态：Worker + Queue + D1 + KV + R2，**删除 Container**；
公网面为单 HTML（0 框架 0 构建 0 依赖）；AI 降级为离线编译表（LLM 是编译器，不是解释器）；
Python 重定位为"对照组实现 + golden 生成器 + 本地模式"。
依赖执行"一进二出"规则：新增任何依赖必须删除两个现有依赖。

### D4｜`main` 冻结规则（本 ADR 生效即生效）

`main` 只接受两类提交：
1. 安全修复；
2. 从 `preview` 提升（`squash` 合并 + `workflow_dispatch` + 40 位 SHA）。

实验组的一切变更不得直接进入 `main`。**本 ADR 是冻结生效前的最后一批常规提交之一。**

### D5｜L0 真相层：把事实变成生成物

文档中的规模数字不再手写，改由 `tools/gen_metrics.py` 生成、`tools/render_docs.py` 渲染、
`tools/falsify.sh` 反向证伪，并由 CI 强制"生成物 == 提交物"。

由此确立**不变量 INV-D**：
> **守卫必须针对真实制品测试。** 任何读取真实配置文件 / schema / 契约的守卫函数，
> 其测试必须至少有一条直接消费仓库中那份真实文件；合成 fixture 只能补充边界条件，不能替代真品。

这条不变量同时解释了 §背景 2 的 45 天故障与文档数字长期矛盾这两个看似无关的问题：
**两者都是"断言指向真实世界，但验证指向玩具世界"。**

### D6｜修订 preview 环境的边界约束

现有规格 `docs/superpowers/specs/2026-08-02-cloudflare-durable-import-and-preview-canary-design.md:18` 规定：

> "Preview 不启用 Container、Cron 或 Queue，不访问新闻源、不调用 AI Provider、不修改生产 D1/R2/Worker。"

实验组需要真实采集，与之直接冲突。**本 ADR 显式修订如下**（不静默绕过）：

| 约束 | 修订后 | 理由 |
|------|--------|------|
| Container | **维持禁止** | 这正是实验变量 |
| Cron / Queue | **允许**（单 target 起步、相位偏移、独立 Queue） | 对照组必须真实运行 |
| 访问新闻源 | **允许** | 对照组的定义 |
| 调用 AI Provider | **维持禁止** | 成本与 key 隔离；且与 D3 的离线编译一致 |
| 发送告警 | **维持禁止** | 实验不得对外产生副作用 |
| 写生产 D1/R2/Worker | **维持禁止** | 隔离底线，由哨兵事件证明 |

原有的合成 canary 角色**完整保留且前置**：每次 preview 部署先跑合成 canary 证明管线，
再允许对照组负载启动。两者是串联，不是替换。

## 不变量

| # | 不变量 |
|---|--------|
| **INV-A** | 任何时刻 `main` 可部署、可回滚、未被实验影响 |
| **INV-B** | 任何"更好"的结论必须有 A/B 两组同时观测数据 |
| **INV-C** | 每次实验产出可复现回执（commit + config digest + 计数 + 计时） |
| **INV-D** | 守卫必须针对真实制品测试 |

## 后果

### 正面

- 生产风险归零：所有实验发生在实验组，失败只意味着不上线
- "更便宜 / 更对等 / 更快"从叙事变为可算术验证的判定
- 文档数字与磁盘事实强制同步，A3 类断言由 `tools/falsify.sh` 持续反向检查
- Python 的 42K 行与 5,448 项测试获得明确生命周期：它**就是**对照组与 golden 基准

### 代价与风险

- 短期需维护两条轨道（L0–L2 约 6 天），长期复用
- 7 天自然时间窗不可压缩
- 实验组与对照组共享同一 Cloudflare 账号，需额度门禁防止互相影响
- 对照组的 `ok` 率本身不达 90%，因此**只能证明相对不劣**，不能证明接近理论最优

### 待解风险（登记）

| # | 风险 | 处置 |
|---|------|------|
| R1 | Worker 免费计划 10ms CPU 无法完成单源采集 | E1 前置测量；不可达则成本停在 $5/月 |
| R2 | 实验组污染对照组（限流/配额） | 相位偏移 + UA 区分 + 对照组 `rate_limited` 上升 >20% 即中止 |
| R3 | 无外部 ground truth | 登记为已知边界；人工标注作为后续独立工作 |
| R4 | `preview` 分支再次腐烂 | 纳入 CI；连续 30 天无提交告警 |

## 推翻条件

本 ADR 的任何一条决策，**凭证据而非意见推翻**。证据形态包括：真实用户的原话记录、
书面付费/合作意向、实测数据。推翻后须新开 ADR 或在本文追加修订记录。

以下条件成立时，本 ADR 必须被修订或废弃，而不是被"解释"：

1. E1 证明 Worker 原生采集 p99 ≥ 10ms → 删容器的前提不成立
2. E2 召回率 < 99% 且经归因无法修复 → 新栈不足以替代
3. L1 隔离证明失败 → 整个对照组设计无效
4. 对照组 `rate_limited` 因实验上升 > 20% → 双轨方案本身有缺陷，需改为时间分片
5. 对照组自身 ok 率 < 90% 且无法修复 → 无有效基准，实验无意义
